# Скилы: кто главный, чтобы правила не спорили

Подключённые скилы местами противоречат друг другу. Проверено по их текстам:
- `frontend-design` требует смелой, необычной эстетики, «не как у всех», активной анимации и не повторять одни и те же решения.
- `better-ui`, `better-typography`, `animate`, `refactoring-ui` требуют сдержанности, точных значений и короткой, нужной анимации.
- `ui-ux-pro-max` даёт свои пресеты анимации (GSAP) и подборки шрифтов.

Если оставить как есть, дизайнер получит противоположные указания и сделает случайное. Поэтому порядок такой.

## 1. Кто главнее при любом споре
1. Слово владельца в чате.
2. ТЗ проекта (`02-tz.md`).
3. Брендбук клиента (`brandbooks/<клиент>/`).
4. Утверждённые макеты (`03-design/`). Разработчик воспроизводит их, а не придумывает своё.
5. Таблица ниже.
6. Общие советы любого скилла.

Пункт выше всегда побеждает пункт ниже. Скилл не отменяет ТЗ и брендбук.

## 2. Кто главный по темам

| Тема | Главный | Помощники, только где главный молчит | Что не применять |
|---|---|---|---|
| Общий стиль и настроение | брендбук клиента; без него `brand-designer` по референсам из `design-library/` и выбору владельца | в режиме «Вау»: `frontend-design` (смелое направление, необычная композиция); в режиме «Стандарт»: `refactoring-ui`. Режимы: `departments/design-taste.md` | «нейронные» шаблоны из `design-taste.md` (раздел 1) без решения владельца |
| Выбор шрифтов | `brand-designer` | подборки пар из `ui-ux-pro-max` | любой шрифт без кириллицы; правило «никогда Inter/системные» из `frontend-design` |
| Размеры, интервалы, переносы, читаемость | `better-typography` | шкала размеров из `refactoring-ui` | значения, противоречащие `better-typography` |
| Палитра и контраст | брендбук; `color-expert` при создании | проверка контраста из `refactoring-ui` | палитры из `ui-ux-pro-max`, если бренд уже задан |
| Иерархия, отступы, группировка, кнопки | `refactoring-ui` | `ui-ux-pro-max` для типовых экранов | |
| Мелкие детали (радиусы, иконки, зоны нажатия, тени) | `better-ui` | | |
| Движение интерфейса (кнопки, меню, формы, появление блоков) | `animate` | точные значения из `better-ui` после решения `animate` | пресеты GSAP `ui-ux-pro-max`, если нет причины |
| Эффектные сцены, анимация при прокрутке, 3D-фоны (режим «Вау») | `ui-designer` по референсам и `departments/wow-effects.md` | `frontend-design`, GSAP, Unicorn Studio, Spline, three.js | эффект без условий качества из `wow-effects.md` (телефон, вес, контраст, `prefers-reduced-motion`) |
| Выбор библиотеки | стек из ТЗ | `pick-ui-library` внутри этого стека | подключать библиотеку «потому что красиво» |
| Варианты | `brand-designer`: варианты стиля целиком. `prototype`: варианты одного блока | | путать уровни: сначала стиль, затем макет, затем варианты блока |
| Русские тексты интерфейса, сайтов, инструкций | `sasha` | тон из `brand` и брендбука | |
| Посты и ответы клиентам | `copywriter` по правилам из его файла | тон из брендбука | `sasha` сюда не относится по своему описанию |
| Референсы, эффекты, компоненты из подборки сайтов (`docs/references.md`) | выбор владельца по `references.html` | идеи для макета, компоненты внутри стека ТЗ | эффекты и библиотеки для статичного сайта S, эффекты вопреки `animate`, любой шрифт без кириллицы или без проверенной лицензии |
| Проверка дизайна | `qa-design` по `better-ui` и `better-typography` | `ux-audit` по запросу для проектов M и L | |

## 3. Когда конфликт остался
Агент не выбирает молча. Он записывает в заметки к работе одной строкой: какие два правила столкнулись, что выбрал и почему. Если выбор влияет на внешний вид или цену, вопрос идёт владельцу.

## 4. Python
`ui-ux-pro-max`, `sasha` и другие скилы предлагают команду `python` или `python3`. Здесь работает только `py -3`.
