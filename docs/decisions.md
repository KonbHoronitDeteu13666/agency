# Решения по архитектуре

## Вложенные субагенты (проверено 29.09.2026)
Документация Claude Code: субагент по умолчанию может вызывать своих субагентов, до трёх уровней ниже основного разговора. Значит, руководители отделов сделаны настоящими агентами, а не регламентами. Ограничение допустимых исполнителей задаётся в `tools: Agent(имя1, имя2)`. Опасение из брифа не подтвердилось. Источник: https://code.claude.com/docs/en/sub-agents

Цепочка с самой глубокой вложенностью: главный → `support-lead` → `dev-lead` → `web-dev`. Это три уровня ниже главного, ровно лимит. Глубже не заходить.

## Главный агент
`agency-lead` включён по умолчанию через `.claude/settings.json` (`"agent": "agency-lead"`). Он единственная точка входа для владельца.

## Цепочка «идея → код» из установленных скиллов
Не используется целиком: она рассчитана на крупный продукт с графом разделов и подробным ТЗ, а у нас проекты на 1–3 дня. Её правила перенесены в облегчённые агенты. Сама цепочка остаётся доступной в сессии отдельно.

## Данные клиентов
Папки `leads/`, `clients/`, `projects/`, `brandbooks/` в `.gitignore`. Репозиторий приватный, но персональные данные клиентов на GitHub не нужны.

## Открыто
- Какие документы нужны без ИП (договор, счёт, акт или иное): решает владелец. `doc-drafter` готовит только черновики.
- Запуск: по плану сначала локально (вариант A), потом лидогенерация в облаке по расписанию.
