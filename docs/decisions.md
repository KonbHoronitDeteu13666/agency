# Решения по архитектуре

## Вложенные субагенты (проверено 29.09.2026)
Документация Claude Code: субагент по умолчанию может вызывать своих субагентов, до трёх уровней ниже основного разговора. Значит, руководители отделов сделаны настоящими агентами, а не регламентами. Ограничение допустимых исполнителей задаётся в `tools: Agent(имя1, имя2)`. Опасение из брифа не подтвердилось. Источник: https://code.claude.com/docs/en/sub-agents

Цепочка с самой глубокой вложенностью: главный → `support-lead` → `dev-lead` → `web-dev`. Это три уровня ниже главного, ровно лимит. Глубже не заходить.

## Главный агент
`agency-lead` включён по умолчанию через `.claude/settings.json` (`"agent": "agency-lead"`). Он единственная точка входа для владельца.

## Цепочка «идея → код» из установленных скиллов
Не используется целиком как есть: она рассчитана на один крупный продукт с интерактивным подтверждением каждого шага, а у нас поток проектов разного размера (S, M, L, см. `departments/project-sizes.md`). Её правила перенесены в агентов, а для проектов M и L шаги «схема разделов и данных» и «ТЗ по этапам» встроены в `tz-writer`. Сама цепочка остаётся доступной в сессии отдельно.

## Данные клиентов
Папки `leads/`, `clients/`, `projects/`, `brandbooks/` в `.gitignore`. Репозиторий приватный, но персональные данные клиентов на GitHub не нужны.

## Открыто
- Какие документы нужны без ИП (договор, счёт, акт или иное): решает владелец. `doc-drafter` готовит только черновики.
- Запуск: по плану сначала локально (вариант A), потом лидогенерация в облаке по расписанию.

## Размеры проектов (исправлено 29.09.2026)
Сначала я принял «1–3 дня» из брифа за общий потолок. Это описывало массовый сегмент (лендинги, боты). Владелец берёт и более крупные проекты, но не сложные многоуровневые. Введены размеры S, M, L: `departments/project-sizes.md`. Для M и L добавлены схема разделов и данных, ТЗ по этапам, QA по этапам, git в сборке.

## Приоритет скилов
Скилы одной категории противоречат друг другу (например, `frontend-design` требует смелой эстетики и активной анимации, `animate` и `better-ui` требуют сдержанности). Порядок старшинства и таблица по темам: `departments/skill-precedence.md`. Агенты дизайна, разработки и QA читают файл перед работой. `frontend-design` убран у `web-dev`, оставлен только у `ui-designer` на этапе выбора направления.

## Список разрешённых агентов у главного (исправлено 29.09.2026)
`tools: Agent(a, b, c)` у главного агента ограничивает набор агентов на всю сессию, а не только его прямые вызовы: руководители отделов видели только те девять имён, `reference-scout`, `brand-designer` и `ui-designer` для них были скрыты («Agent type not found»). У `agency-lead` теперь `Agent` без списка. Дисциплину «главный вызывает руководителей, а не исполнителей» держит текст его инструкции.
